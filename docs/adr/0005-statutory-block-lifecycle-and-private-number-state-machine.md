# Statutory Block Lifecycle, Private Number Exchange State Machine and TSLW Protocol

We enforce a strict finite state machine for maintenance blocks under Indian Railways General and Subsidiary Rules (G&SR:2018, GR 3.68, SR 4.42, SR 4.09, SR Chapter 15):
1. `PROPOSED`: Generated by the AI optimizer or controller request; requires multi-department pre-approval consent (Track, Signal, Traction) enforcing RDSO simultaneous possession mandates.
2. `APPROVED`: Verified by division control; corridor slots locked. Blocks > 4 hours or non-interlocking (NI) works > 3 days require explicit `DIVISIONAL_AUTHORITY` sanction (Railway Board letter 16.06.2022).
3. `ACTIVE`: Officially granted by the Station Master; requires a validated Station Master **Private Number (PN)** and field engineer token for Disconnection Notice (Form T/351).
4. `COMPLETED`: Officially cancelled and track restored; requires a Reconnection Notice (Form T/351-B), clearance PN, and mandatory Temporary Speed Restriction (TSR) entry.
5. `TSLW_ACTIVE`: If a block overruns or track is obstructed, Temporary Single Line Working (TSLW) is governed by **Form T/D 602** (Line Clear Ticket + Authority to Pass Signals at 'ON' + Caution Order) enforcing statutory speeds ($25\text{ km/h}$ pilot train, $15\text{ km/h}$ facing points/crossovers, booked speed for subsequent running trains).

Treating block statuses as freeform editable strings allows bypassing statutory railway safety procedures. Enforcing state transitions with numeric Private Number audit fields and Form T/D 602 line-clear authorities guarantees strict regulatory compliance.
